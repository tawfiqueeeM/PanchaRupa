1. **Codex → Antigravity.** Paste the exact prompt Codex writes. It identifies the route, action and state fields, sample inputs, acceptance checklist and permitted UI files.

3. Use separate branches or worktrees. Antigravity owns assigned UI and presentation files. Codex owns model, interfaces, tests and integration. Agree on the interface before either task depends on it. Codex stages and reviews both changes before the daily push.

## Conference paper track · SIMS EUROSIM 2027

**Working title** · *Discrete-Event Simulation of Seasonal Staffing and Inventory in a Small Tea Factory*

**Research question** · Under identical fresh-leaf deliveries and customer orders, how do seasonal staffing and a pre-winter stock target affect order fulfillment, labor use, and inventory in a small tea factory?

**Scope** · Merge leaf procurement, production scheduling, worker shifts, inventory and fulfillment, and the integrated factory simulation. Model a dryer outage as an equipment availability event. The detailed PLC dryer and SD-anlegg remain independent portfolio demos. The research model runs from a single command, and the web pages use the same model or its exported results.

**Target venue** · [SIMS EUROSIM 2027](https://www.automaatioseura.fi/simseurosim2027/), 22–23 September 2027 in Oulu. Verify the submission requirements and deadline when the organizers publish the call. [ASIM SPL 2027](https://www.asim-gi.org/en/spl2027/paper-submission/registration) provides an alternate planning benchmark, with abstract and full-paper deadlines of 16 April and 9 May 2027 respectively. Treat March as the internal manuscript target and confirm venue requirements before submitting.

- Keep exogenous inputs identical within each comparison. If the simulator uses random draws, use matched scenario seeds across policies, rerun across seeds, and report variability. Report roster effects at both stock policies, stock-policy effects at both rosters, and whether their combined effect changes the outcome.
- Report on-time orders, winter fill rate and stockouts, overtime, idle hours, labor hours per released kg, ending inventory and shared-equipment utilization. ## End-of-day GitHub routine

1. Use the existing PanchaRupa repository if available or create one once the owner and access are confirmed. Use a private integration branch or private repository for checkpoints until public release is approved.
2. Review the branch diff and ensure no secrets or private factory, supplier or customer data are staged. Merge reviewed pieces, run the relevant tests, and record status and known blockers in the daily log.
3. Commit and **push to GitHub at the end of every workday**, including partial days. If integration is blocked, push the work branch or a clean checkpoint with a short status note. Keep incomplete demos out of public release.
4. Confirm the remote branch contains the commit. Log the date, branch, commit, modules touched, tests run and next handoff. If authentication or access blocks the push, retain the local commit and resolve access at the next opportunity.
5. A CV-ready demo must open at its own URL without a login, let the recruiter run and reset the scenario, and link to its GitHub source and observed evidence. Calling a browser control demo “native TIA Portal” requires actual native implementation and validation.

## Model assumptions shared by all windows

The active-month target is around 1,000 kg total with variable daily production and nearly daily operations. Golden tea depends on suitable leaf deliveries. No fresh leaf is available in January and February in the seasonal baseline. Use opening released stock for winter packing or dispatch. Include bulk auction packs and both 50 g and 100 g retail bottles. Keep synthetic figures separate from the founder-reported growth from 100 to roughly 1,000 kg per active month.
